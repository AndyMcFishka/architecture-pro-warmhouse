### 1. Описание функциональности монолитного приложения

- Всё управление идёт от сервера к модулям отопления [протокол доставки команд не описан]

**Телеметрия:**

- Пользователи могут просматривать текущую температуру в своих домах через веб-интерфейс [наличие веб-интерфейса подтверждено только условием]

### 2. Анализ архитектуры монолитного приложения

- Язык программирования: Go 1.22
- Веб-фреймворк: Gin
- База данных: PostgreSQL, доступ через pgx и пул соединений pgxpool
- API: HTTP, данные передаются в JSON
- Архитектура: Монолитная, обработка запросов и работа с данными находятся в одном приложении. Код разделён на пакеты handlers, models, db и services. Отдельный слой бизнес-логики практически отсутствует
- Внешние зависимости: PostgreSQL и temperature-api. Реализация temperature-api в текущей заготовке отсутствует
- Взаимодействие: Синхронное. Сервер инициирует управление устройствами и получение температуры, устройства инициируют регистрацию. При получении списка температурные сенсоры опрашиваются последовательно [клиентские HTTP-запросы могут обрабатываться конкурентно]
- Развёртывание: Docker и Docker Compose [настройки PostgreSQL и temperature-api не завершены]. По условию обновление требует остановки приложения. В коде предусмотрено корректное завершение сервера

### 3. Определение доменов и границы контекстов

Предметная область — управление умным домом и наблюдение за его состоянием. Контексты разделены по бизнес-обязанностям: каждый отвечает за свои данные и правила. Выделение контекста само по себе не означает выделение отдельного микросервиса.

**As-Is**

В монолите выделяем три логических контекста. В существующем коде их границы явно не оформлены: учёт сенсоров и получение температуры смешаны в обработчиках запросов.

| Домен / контекст | Ответственность | Границы контекста |
| --- | --- | --- |
| Регистрация и учёт устройств | Регистрация устройства, хранение его идентификатора, типа, расположения и статуса, изменение и удаление записи | Описывает, какие устройства есть в системе; получение показаний относится к телеметрии, выполнение команд — к управлению отоплением |
| Телеметрия | Получение и просмотр текущей температуры и времени обновления показаний | Работает с измерениями; не регистрирует устройства и не принимает решения об их включении или выключении |
| Управление отоплением | Включение и выключение отопления по запросу пользователя | Отвечает за управление отоплением; не ведёт реестр устройств и не получает показания для отображения пользователю |

Управление отоплением выделено по условию задания: доставка команд оборудованию в предоставленном коде не реализована. Изменение записи сенсора само по себе не означает выполнение команды физическим устройством.

**To-Be**

Для целевой системы уточняем существующие контексты и добавляем новые области ответственности.

| Домен / контекст | Ответственность | Границы контекста |
| --- | --- | --- |
| Управление домами и доступом | Учёт домов, участников и их прав на дом | Определяет, кто имеет доступ к дому; не хранит характеристики устройств, показания и команды |
| Регистрация и учёт устройств | Самостоятельное подключение устройств, их описание, типы и привязка к дому | Владеет реестром устройств; права на дом получает из контекста доступа, измерения и выполнение команд относятся к другим контекстам |
| Телеметрия | Получение, хранение и просмотр измерений, определение их актуальности | Владеет показаниями и их историей; не управляет устройствами и не определяет условия автоматизации |
| Управление отоплением | Правила включения и выключения отопления, создание команд и учёт результатов | Отвечает только за отопление; использует реестр и проверку доступа, не управляет освещением и воротами |
| Управление освещением | Правила включения и выключения света, создание команд и учёт результатов | Отвечает только за освещение; не ведёт реестр устройств и не управляет другими видами оборудования |
| Управление воротами | Правила запирания и отпирания ворот, создание команд и учёт результатов | Отвечает только за ворота; не заменяет аппаратные блокировки безопасности контроллера |
| Автоматизация и сценарии | Пользовательские правила, проверка условий и запуск действий | Использует показания телеметрии и вызывает соответствующий контекст управления; не дублирует его правила выполнения команд |
| Управление видеонаблюдением | Команды камерам, их результаты и предоставление доступа к видеопотокам со звуком | Отвечает за функции видеонаблюдения; учёт камер остаётся в реестре устройств, права на дом — в контексте доступа |

Например, в сценарии «если температура ниже 18 °C — включить отопление» телеметрия предоставляет показание, автоматизация проверяет условие, а управление отоплением создаёт команду и отслеживает результат.

# Задание 5. Работа с docker и docker-compose

Перейдите в apps.

Там находится приложение-монолит для работы с датчиками температуры. В README.md описано как запустить решение.

Вам нужно:

1) сделать простое приложение temperature-api на любом удобном для вас языке программирования, которое при запросе /temperature?location= будет отдавать рандомное значение температуры.

Locations - название комнаты, sensorId - идентификатор названия комнаты

```
	// If no location is provided, use a default based on sensor ID
	if location == "" {
		switch sensorID {
		case "1":
			location = "Living Room"
		case "2":
			location = "Bedroom"
		case "3":
			location = "Kitchen"
		default:
			location = "Unknown"
		}
	}

	// If no sensor ID is provided, generate one based on location
	if sensorID == "" {
		switch location {
		case "Living Room":
			sensorID = "1"
		case "Bedroom":
			sensorID = "2"
		case "Kitchen":
			sensorID = "3"
		default:
			sensorID = "0"
		}
	}
```

2) Приложение следует упаковать в Docker и добавить в docker-compose. Порт по умолчанию должен быть 8081

3) Кроме того для smart_home приложения требуется база данных - добавьте в docker-compose файл настройки для запуска postgres с указанием скрипта инициализации ./smart_home/init.sql

Для проверки можно использовать Postman коллекцию smarthome-api.postman_collection.json и вызвать:

- Create Sensor
- Get All Sensors
